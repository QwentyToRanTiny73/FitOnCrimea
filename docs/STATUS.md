## Что сделано

### На живом сайте (`main`, до PR #8 включительно)

- Next.js 14 со статическим экспортом на GitHub Pages. Один workflow `.github/workflows/nextjs.yml`:
  lint, проверка типов, сборка, проверка результата `scripts/verify-export.mjs`.
- Каталог из 24 бальзамов: поиск, фильтры по разделам, страницы товаров, Schema.org, sitemap.
- Страницы: «Точки массажа», «О бренде», «Вопросы», «Контакты», «Политика конфиденциальности»,
  «Избранное», «Личный кабинет» (демо).
- Нижнее меню на телефоне, мобильная панель «Купить» на странице товара.
- Удалены выдуманные факты (сроки годности, «без парабенов» и др.). Контакты взяты из брошюры.

**PR #7 — оформление по брошюре «Целебные бальзамы Крыма» и админка**
- Палитра снята с брошюры, цвета — токены в `tailwind.config.ts`. Шрифты Old Standard TT,
  Ruslan Display, Inter. Пергамент, опалённые края, золотые поля, рамка-марка — `globals.css`.
- Орнаменты в `src/components/ui/Brochure.tsx`: эмблема, лента со слоганом, золотые травы-силуэты,
  восьмигранная баночка — плейсхолдер для товаров без фото.
- Кабинет администратора `/admin`: вход ключом GitHub, правка карточек, фото с компьютера,
  скрытие товаров, публикация одним коммитом (`overrides.json` + фото), таблица CSV для Excel.
- Навигация по итогам исследования сайтов krimroza.ru, socrimea.ru/АЭМСЗ, zarstvo.su,
  markakrima.com, levrana.ru.

**PR #8 — интерактивная схема точек массажа (`/massage-points`)**

**Кабинет администратора — как в интернет-магазине**

- Вход по логину и паролю, которые владелец задаёт сам при первом входе. Пароль шифрует ключ GitHub

## Принятые решения

| Решение | Почему |
|---|---|
| GitHub Pages, статический экспорт | Бесплатно, без сервера. Покупки идут через Ozon |
| Покупка только на Ozon, корзины нет | Бизнес-правило владельца |
| Вход администратора логином и паролем, которые открывают зашифрованный ключ GitHub | Сервера нет. Хэш пароля в коде страницы виден всем и подбирается; здесь пароль расшифровывает ключ, а права на публикацию проверяет GitHub |
| Вход хранится на устройстве, на второе переносится файлом | Хранить зашифрованный ключ в публичном репозитории — лишний риск |
| Оформление — фиксированные места и баннеры, а не свободный конструктор страниц | Статический сайт и стиль брошюры: замена картинок и баннеры не ломают вёрстку |
| Кабинет без ссылки с витрины | Покупателям он не нужен; как в магазинах, вход по прямому адресу |
| Публикация = коммит `overrides.json` и фото | Без сервера и CMS. Вся история и откат — в Git |
| `sanitize.ts` для всех правок | Ошибка в данных не должна ломать сборку и сайт |
| Стиль по брошюре: засечки, пергамент, акварель | Запрос владельца. Отличие от конкурентов |
| Тексты только из брошюры и данных владельца, черновики помечены | Правило «не выдумывать факты» |
| При расхождении таблицы владельца и брошюры берётся брошюра | Брошюра — напечатанный источник бренда; таблица была короче |
| Опечатки брошюры исправлены, каждая записана в пометке | На витрине опечатки выглядят небрежно; пометка позволяет сверить с оригиналом |
| Иконки разделов — фрагменты акварелей брошюры, а не новые рисунки | Запрос «в стилистике как на фотографиях»: тот же художник и та же техника |
| Иллюстрации товаров вырезаны из фото разворотов | Других изображений товаров нет; заменить при появлении скана или макета |
| Выключка по ширине только на ПК | На узком экране она даёт дыры между словами |
| Без имён владельцев и сотрудников, контакты из брошюры | Бизнес-правило |
| Один workflow и проверка `out/` перед публикацией | Раньше были двойные деплои и «README вместо сайта» |
| Код разложен по `config/`, `data/`, `services/`, `providers/` | Правка в одном месте |
| Презентация-шпаргалка не в репозитории | Личный материал владельца |
| В схеме точек бальзамы подбираются только по совпадению показаний | Брошюра говорит о массаже «с Крымским бальзамом» без привязки к конкретному |
