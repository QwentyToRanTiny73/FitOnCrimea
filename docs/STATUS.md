## Что сделано

### На живом сайте (`main`)

- Next.js 14 со статическим экспортом на GitHub Pages. Один workflow `.github/workflows/nextjs.yml`:
  lint, проверка типов, сборка, проверка результата `scripts/verify-export.mjs`.
- Каталог из 24 бальзамов: поиск, фильтры по разделам, страницы товаров, Schema.org, sitemap.
- Страницы: «Точки массажа» (схема 26 точек из брошюры), «О бренде», «Вопросы», «Контакты»,
  «Политика конфиденциальности», «Избранное», «Личный кабинет» (демо).
- Нижнее меню на телефоне, мобильная панель «Купить» на странице товара.
- Удалены выдуманные факты (сроки годности, «без парабенов» и др.). Контакты взяты из брошюры.

**Данные**
- 5 бальзамов сверены со страницами брошюры дословно (пометки «Брошюра, с. N» в `balms.ts`):
  «Гладкие пятки», «Здоровые суставы», «Белоснежка», «Омолаживающий» (бывший «Лимонник и роза»),
  «Антицеллюлитный». У двух из них состав из сводной таблицы владельца не совпадал с брошюрой —
  заменён на брошюрный.
- Новые поля товара: `description`, `subtitle`, `hidden`.
- Правки из `overrides.json` проходят через `sanitize.ts`. Неверные данные отбрасываются и не ломают сборку.

**Кабинет администратора (`/admin`)**
- Вход ключом доступа GitHub (fine-grained token). Права проверяет GitHub: пускает только тех,
  у кого есть право записи в репозиторий.
- Вкладки: «Товары», «+ Новый товар», «Публикация», «Таблица Excel», «Справка».
- В карточке товара:
  - правка любых полей;
  - фото с компьютера кнопкой или перетаскиванием;
  - выбор обложки;
  - «Скрыть» — снять товар с витрины без удаления.
- Публикация одним коммитом. Фото уходят в `public/products/`, правки — в
  `src/data/catalog/overrides.json`. Сайт пересобирается автоматически.
- Таблица CSV для Excel: выгрузка и загрузка. В черновики попадают только изменённые поля.

**Навигация** (по итогам исследования сайтов krimroza.ru, socrimea.ru/АЭМСЗ, zarstvo.su, markakrima.com, levrana.ru)
- Порядок главной: обложка → полоса доверия → «Что вас беспокоит?» → хиты → о серии →
  подборки → цифры → линейки → точки массажа → «Как купить».
- Подсказки «Часто ищут» в каталоге. Поиск понимает окончания слов.

**Проверки**
- `npm run check` — проходит.
- Браузерные тесты (Playwright) — 49/49 на телефоне и ПК:
  - страницы без ошибок и горизонтальной прокрутки;
  - поиск и фильтры;
  - вход, правка, фото, новый товар, скрытие;
  - Excel, публикация.
- Сборка из опубликованного `overrides.json` проверена: новый товар получает свою страницу,

## Принятые решения

| Решение | Почему |
|---|---|
| GitHub Pages, статический экспорт | Бесплатно, без сервера. Покупки идут через Ozon |
| Покупка только на Ozon, корзины нет | Бизнес-правило владельца |
| Вход администратора ключом GitHub, а не паролем | Права проверяет GitHub. Хэш пароля в коде страницы подбирается. Ключ всё равно нужен для публикации |
| Публикация = коммит `overrides.json` и фото | Без сервера и CMS. Вся история и откат — в Git |
| Черновики админки хранятся в браузере | На статическом сайте нет бэкенда |
| `sanitize.ts` для всех правок | Ошибка в данных не должна ломать сборку и сайт |
| Стиль по брошюре: засечки, пергамент, акварель | Запрос владельца. Отличие от конкурентов: у всех шрифты без засечек и фото на белом |
| Тексты только из брошюры и данных владельца, черновики помечены | Правило «не выдумывать факты» |
| Без имён владельцев и сотрудников, контакты из брошюры | Бизнес-правило |
| Один workflow и проверка `out/` перед публикацией | Раньше были двойные деплои и «README вместо сайта» |
| Код разложен по `config/`, `data/`, `services/`, `providers/` | Правка в одном месте. Сервис подключается заменой реализации в `services/index.ts` |
| Презентация-шпаргалка не в репозитории | Личный материал владельца |
