# Запуск сайта на своём домене (REG.RU)

Сайт собирается на GitHub и сам выкладывается на хостинг REG.RU по FTP при каждом
обновлении `main` — в том числе после публикации из кабинета администратора.
Названия пунктов в панелях REG.RU могут отличаться от написанных здесь — ориентируйтесь по смыслу.

## 1. Домен и хостинг (в личном кабинете REG.RU)

1. Продлите домен `phyton-crimea.ru`. Включите автопродление и двухфакторный вход в аккаунт.
2. Закажите хостинг для одного сайта (обычный виртуальный хостинг с панелью управления).
   Сайт — набор HTML-файлов, PHP и база данных не нужны.
3. Привяжите домен к хостингу. Если домен и хостинг в одном аккаунте REG.RU, это делается в панели;
   DNS-серверы хостинга REG.RU подставит сам. Изменения DNS расходятся до суток.
4. В панели хостинга выпустите бесплатный SSL-сертификат (Let's Encrypt) для домена и включите
   переход с `http` на `https`.
5. Узнайте **папку сайта** на хостинге (в панели — раздел сайтов, «корневая папка»; в FTP она
   обычно выглядит как `www/phyton-crimea.ru`) и **доступ по FTP**: адрес сервера, логин, пароль.
6. Спросите в поддержке, работает ли на хостинге **FTPS** (FTP с шифрованием). Скрипт выкладки
   по умолчанию использует его, чтобы пароль не передавался открыто.

**Старый сайт.** Если в папке сайта лежат файлы старого магазина, сделайте их копию (на всякий
случай) и удалите их из папки до первой выкладки. Скрипт не трогает чужие файлы, а старый
`index.php` может открываться вместо нового сайта.

## 2. Настройки в GitHub

Репозиторий → **Settings → Secrets and variables → Actions**.

Вкладка **Secrets** (видны только сборке, никому не показываются):

| Имя | Что вписать |
|---|---|
| `FTP_HOST` | адрес FTP-сервера из письма или панели REG.RU |
| `FTP_USER` | логин FTP |
| `FTP_PASSWORD` | пароль FTP |

Вкладка **Variables**:

| Имя | Значение |
|---|---|
| `DEPLOY_TARGET` | `regru` |
| `SITE_URL` | `https://phyton-crimea.ru` |
| `FTP_DIR` | папка сайта, например `www/phyton-crimea.ru` |
| `FTP_TLS` | не создавать. `off` — только если поддержка подтвердила, что FTPS нет |

Пароли и ключи не пишите в код, в README и в чат — только в Secrets.

## 3. Первая выкладка

1. **Actions → Deploy site → Run workflow** (ветка `main`).
2. Через 2–4 минуты откройте `https://phyton-crimea.ru`. Проверьте каталог, страницу товара,
   схему точек и вход в кабинет: `https://phyton-crimea.ru/admin/`.
3. Если запуск красный — откройте его: шаг **Deploy to hosting (FTP)** пишет причину по-русски
   (неверный пароль, нет папки, не удалось соединиться).

## 4. После запуска

- **Settings → Pages → Unpublish site**, чтобы копия на github.io не конкурировала с доменом в поиске.
- В кабинете администратора ничего менять не нужно: «Опубликовать» по-прежнему отправляет
  правки в репозиторий, сборка выкладывает их на хостинг.
- Добавьте сайт в Яндекс.Вебмастер и укажите `https://phyton-crimea.ru/sitemap.xml`.
- Вход в кабинет на новом адресе настраивается заново (логин, пароль, ключ GitHub):
  данные входа хранятся в браузере и привязаны к адресу сайта.

## Что лежит на хостинге

- Файлы сайта из `out/` и `.deploy-manifest.json` — список выложенного, по нему скрипт
  загружает только изменившиеся файлы и удаляет только свои устаревшие.
- `.htaccess` — страница 404, заголовки безопасности (запрет встраивания сайта в чужие страницы,
  политика загрузки скриптов и картинок) и кэширование. Если подключите Яндекс.Метрику,
  её адреса нужно добавить в `Content-Security-Policy` в `public/.htaccess`.

## Вернуться на GitHub Pages

Удалите переменную `DEPLOY_TARGET` (или задайте любое другое значение) и запустите сборку.
